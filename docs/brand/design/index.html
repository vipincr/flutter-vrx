Guideline

vrx identity

The vrx wordmark, its mark, the palette and the system fonts, and every place they appear. Approved by the owner on 2026-11-14 (the design canvas: "vrx identity and boot splash", a private claude.ai artifact the owner holds).

This directory is the identity package (plan 0024), the one source of every name, identifier, colour, logo and face a person sees on a vrx device: brand.toml (names, identifiers, palette, font roles), this document, logo/<shape>-<ground>.svg and fonts/ with their licences. Every surface is built from it: the boot splash, the bootloader logo, os-release, the hostname, the USB gadget, Matter, the file names, the kernel release, the UIs. No recipe, applet or document carries a hand-made copy of the logo or spells a brand colour. vrx's logo SVGs are written from the geometry below by scripts/vrx-logo.py; every raster is rendered from the SVGs by vrx-brand (meta-vrx-distro/recipes-core/vrx-brand), the same tool a client's package goes through.

A white-label client's identity replaces this package on its own brand/<client> branch of every vrx repo (scripts/brand-apply.sh, docs/howto/WHITE_LABEL.md); the product keeps "powered by vrx" on its About screen, in os-release (VRX_POWERED_BY) and as the kernel release's -vrx.

Every vrx repo carries the active identity in its own docs/brand/, written by scripts/brand-sync.sh from this package and stamped with its revision; scripts/brand-sync.sh --check fails on a copy that has drifted.

The mark

The v is a prism of three strata, seen from above: three layers narrowing to a point, the way an operating system narrows from the applets through the system to the kernel. The tip is the kernel, and it carries the one accent.

The wordmark is one strip of material folded twice. The v's top layer, the r's shoulder and the x's back stroke share a single top line, parted by two seams; the r's stem and the x's strokes are where the strip turns down. One light rule colours all of it: faces that lie flat are paper, faces that turn down are shade.

There are no curves. Every edge is a straight line, which is what lets a bootloader, a 1-bit framebuffer and a 16 px favicon draw it as exactly as print does.

Typography

RoleFaceFiles
UIFira SansLight, Regular, Medium (the three weights the UI uses)
Console, terminal, logs, codeFira CodeRegular, Bold (the editor's keyword emphasis)
Math symbols (fallback)Noto Sans MathRegular
Music symbols (fallback)Noto MusicRegular

About 2.6 MB in all, in one package (vrx-fonts), with fontconfig making them the defaults: sans-serif, system-ui and serif resolve to Fira Sans, monospace to Fira Code, and both fall back to the two symbol faces, so a math operator or a note value renders inside any text.

Why these. A system font has constraints a design font does not: a licence that allows shipping it inside firmware (SIL OFL 1.1 for all four), hinting that holds at small pixel sizes on low-DPI panels (the Brain is 178 ppi at 854 x 480), coverage of Latin, Greek and Cyrillic, and a true pair so the UI and the console read as one system. Fira Sans was drawn for Firefox OS, an operating system's UI on small phone screens, and Fira Code is its monospace sibling with programming ligatures. JetBrains Mono, Cascadia Code and Iosevka were weighed as the mono and lost on pairing (none has a UI sans of its own); Hack is the strongest no-ligature option and stays the named alternative if ligatures ever cost more than they give. Roboto and Liberation, the faces before, are gone.

Ligatures: on in the terminal, off where text is shown verbatim (logs, code listings, file names), because != drawn as ≠ in a log is a lie about the bytes.

Math and music are part of the system, not an add-on: the evrx-rt runtime writes flats, sharps, the diminished ring and the major-seventh triangle inside running text (VRX_MUSIC_* in its ui_icons.h), and vrx keeps every such character renderable everywhere.

Rules

  • The logo is always lowercase, always the geometry above. Never retype it in a font, stretch it, outline it, add a gradient, or put it on a busy image.
  • One accent per surface.
  • A surface that needs a new size or format adds a command to vrx-brand and renders at build time; it never commits a rendered file.
  • The fonts are the four above. A new face needs the owner's decision and an entry in this document; a new weight needs a screen that uses it.
